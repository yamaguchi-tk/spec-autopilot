# spec-autopilot: 要件を壁打ちで詰め、合意したら QA まで自走する、かっちりした軽いハーネス

- 日付: 2026-11-15
- 状態: 承認済み（2026-11-15、ユーザー「承認する」）
- ADR: `docs/adr/2026-11-15-switch-harness-to-spec-autopilot.md`

## 目的

依頼（2026-11-15、ユーザー）:

> 欲しいのは、要件と作り方とQAの方向性、制約事項を合意したらQAまで自走するハーネス
> HITLで止まるのは要件が満たせないとき
> 袋小路も自律的に解決し、スピードとコストの両立をしたい
> テトリスで1時間かかるのは使えない
> 要件は人間と壁打ちして詰めていきたい
> 人間が最初に出した要件は本当に欲しいものを正しく表しているとは限らない
> ADRとSpecsは欲しい

追加の発言（2026-11-15、最初の草案の後）:

> superpowersよりもかっちりしたハーネスを作りたかった
> KDDIアジャイル開発センターとかの事例も調べてみて

追加の発言（2026-11-15、承認の後。R9 を足した）:

> 中断と再開、同じPCで違うアカウントへの引き継ぎも出来るようにしておいて欲しい
> コンパクション後の再開が確実に出来るようにも

## 要件

- R1: 依頼を受けたとき、ハーネスは依頼を言い直し、なぜ欲しいのかを問い、問いを 1 回に 1 つにして要件を詰める。
- R2: 合意のとき、ハーネスは要件・作り方・QA の方向性・制約・予算を 1 つの spec にまとめ、人の承認を 1 回で受ける。
- R3: 承認の後、ハーネスは人に確認せずに計画・TDD 実装・レビュー・QA・PR 作成まで進める。
- R4: 合意した要件を満たす方法が無いと分かったときだけ、ハーネスは満たせない要件・理由・証拠・選択肢を 1 通で人に示す。
- R5: 同じ失敗が続いたとき、ハーネスは原因を調べ、それでも続けば作り方を変えて ADR に残し、人に聞かずに進む。
- R6: 完了のとき、spec・ADR・QA の証拠が repo に残り、要件→タスク→証拠の対応を script が検査する。
- R7: 承認の後に検査が通っていないとき、ハーネスは turn を終えない（予算の 2 倍を過ぎたときと、満たせない要件を記録したときを除く）。
- R9: 中断・compaction の後や、同じ PC の別アカウントで同じ worktree を開いたとき、ハーネスは続きのある spec の状態と残りを新しい文脈に渡し、人に聞かずに続ける。
- R8: 小さい新規タスク（落ち物パズル程度）のとき、着手（init）から完了まで、人の返事待ちを含めて 60 分を超えない。承認から完了までは 30 分以内に終える。

## 非目標

- GDD の hook・gate・state machine の再実装
- 要件・設計段の LLM レビュー
- チームでの運用規則（個人の作業を対象にする）

## 作り方

成果物の型（`docs/specs/<日付>-<slug>/` の spec.md・tasks.md・qa.md・state.json と `docs/adr/`）を固定し、`scripts/autopilot.py` が lint・承認の記録・完了の検査を行う。Stop hook 1 本が、自走中に検査が通るまで turn を終えさせない。実装は Sonnet、最後のレビューは Opus の agent。手順は `/autopilot` 1 本。

## QA の方向性

| 要件 | 確かめ方 | 合格基準 |
|---|---|---|
| R1 | 落ち物パズルの通しの計測で、壁打ちの問いを読む | 問いが 1 回に 1 つで、なぜを問うている |
| R2 | 同上 | 承認が 1 回 |
| R3 | 同上 | 承認の後に人への問いが 0 |
| R4 | `tests/test_autopilot.py` の block・approve のテスト | 要件の番号と証拠が無い block を拒む。人の発言の記録が無い approve を拒む |
| R5 | `tests/test_autopilot.py` の fail・rework・review のテスト | 失敗のある巡が 2 巡続いたら調査、3 巡続いたら作り直し、2 回の作り直しで人へ |
| R6 | `tests/test_autopilot.py` の check のテスト | 対応の欠け・証拠の無いテスト名・承認後の spec の変更を拒む |
| R7 | `tests/test_autopilot.py` の Stop hook のテスト | 自走中で検査が通らないと block、done・blocked・予算の 2 倍で放す |
| R9 | `tests/test_autopilot.py` の SessionStart hook と status のテスト | compact・resume・startup・clear で状態と残りが文脈に入り、別のセッション id でも引き継いだ後に Stop hook が止める |
| R8 | 落ち物パズルの通しの計測 | `autopilot.py done` の着手からの分数が 60 以下、承認からの分数が 30 以下 |

## 制約

- 予算: 120 分
- 追加は 1,000 行以内（root CLAUDE.md の 1 PR の目安）
- 外部の依存を足さない（Python 標準ライブラリだけ）
- ユーザーの global CLAUDE.md の安全規則が優先する

## 止まる条件

- 合意した要件のどれかを満たす方法が無いと分かったとき
- 合意の外で、取り消せない操作（GDD の無効化などの settings の変更、マージ）が要るとき
