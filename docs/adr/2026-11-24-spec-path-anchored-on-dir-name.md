# prompt の spec のパスは、spec のディレクトリの名前を手がかりに引く

- 状態: 採用
- 日付: 2026-11-24

## 背景
この spec の最初の ADR（docs/adr/2026-11-23-implementer-launch-gate.md）は、実装役の起動を PreToolUse hook で止め、prompt に書かれた spec の state.json を読むと決めた。prompt からパスを切り出す形は、3 巡続けて R3 の high を出した。字の種類で区切ると、空白・日本語を含むパスと、日本語・全角の記号が隣り合うパスを拾えなかった。区切りに頼らずにファイルシステムの一覧（listdir）と字のまま突き合わせると、NFD で保存された名前と、読めない祖先のディレクトリで拾えなかった。行き詰まりを生んだ前提は、「パスの字の並びを、prompt の中の字の種類か、ファイルシステムの一覧の字で切り出す」ことだった。

## 決定
- spec のディレクトリの名前は `CLI init` が `<日付>-<英小文字・数字・ハイフン>` で作るので、prompt の中の `docs/specs/<その形の名前>` を手がかりにする
- 手がかりごとに、同じ行でその前にある `/` と `~/` の位置を始まりの候補にし、候補から手がかりまでの文字列を spec のディレクトリとして、`state.json` があるかを stat で確かめる。payload の cwd とその祖先の下の `docs/specs/<名前>` も候補にする
- 一致を決めるのはファイルシステム（stat）で、字を比べない。このため正規化を問わない照合（APFS の NFC・NFD）と、実行だけの祖先のディレクトリの下でも、今までの `is_file()` と同じに引ける
- 見つけた spec は realpath で重ねて、同じ spec を 1 度だけ数える
- 候補の数は、手がかりの数 × その前の `/` の数で、行の長さに対して線形に収まる

## 退けた案
- 行と一覧の名前を NFC にそろえ、listdir が落ちたら stat に戻す: 同じ形の修正を足すことになり、ほかの正規化（大文字小文字を区別しない FS など）で同じ型の穴が出る
- prompt を読まず、セッションの記録に載った spec だけを見る: R1・R2 が prompt に書かれた spec で判定すると定めているので、要件が変わる

## 結果
- 手がかりの名前を書かずに、spec のディレクトリの親だけを書いた prompt は拾わない（今の R1 の扱いと同じく deny）
- `docs/specs/` の上の部分に改行を含むパスは拾わない
