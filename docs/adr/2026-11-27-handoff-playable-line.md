# ADR: 最後のタスクを閉じた handoff が「遊べます」の行を促す

- 日付: 2026-11-27
- 状態: Accepted
- spec: docs/specs/2026-11-27-handoff-playable-line

## Context
0.1.16 のハンズオンの試走で、触れる状態は送信の約 13 分後にできたが、main は commands/autopilot.md の「遊べます」の行を出さず、人が知ったのは done の 23 分 48 秒後だった。この行は文書の指示だけで、M のタスク分割ではどの実装役の後に出すかも決まっていなかった。

## 選択肢
1. **最後のタスクを閉じた handoff の OK の出力に、行を出すよう促す 1 行を足す**
   - 得るもの: main が必ず読む出力に、出す時点と一緒に現れる。判定は変えない
   - 失うもの: 出すのは main のままなので、無視されれば出ない
2. **autopilot.md の文を強める**
   - 失うもの: 今の文が無視された。同じ形の指示を強めても確かめられない
3. **評価役を起動する前に、行が出たかを hook で止める**
   - 失うもの: hook の判定が増え、main の text を読む検査を足すことになる。1 で足りなければ考える

## Decision
1 を選ぶ。触れるまでの時間は、マージの前に、この worktree の plugin で同じ依頼文の試走を 1 回回して測る。

## Consequences
- 最後のタスクを閉じた handoff だけが促す行を出す。途中のタスクの handoff は今と同じ
- 試走が 10 分を超えたら、承認の前の M の試作（1 本目の spec の ADR の選択肢 3）を人に戻して決める
