# ADR: 大きさ S の草案と試作を、書く側・止める側・試作の 3 か所の文で S の目安に収める

- 日付: 2026-11-27
- 状態: Accepted
- spec: docs/specs/2026-11-27-s-prototype-size

## Context
ハンズオンの試走（2026-11-27、Sonnet 5.5、新しい repo）で、大きさ S の試作が起動から 10 分を超えた。依頼文を「シンプル」「基本の操作だけでよい」に絞っても、要件は上限の 12 個まで埋まり、本体 342 行・テスト 789 行になった（S の目安は 200 行）。絞らない依頼文では、公式ガイドラインの細部が要件に入り、本体 837 行・テスト 1,238 行で、8 分を超えても試作が終わらなかった。

feature の playbook は普通に付く機能を草案に足させ、上限は要件の数だけを決めている。新しい repo では大きさを表で決めて書き、行数を確かめる段が無い。実装役はテストの数の上限を持たず、時間はほぼ出力の生成で決まる。

## 選択肢
1. **playbook・照合役・実装役の 3 か所の文を直す**
   - 得るもの: 草案を書く時点、人に示す前、試作を書く時点の 3 か所で、同じ目安（本体 200 行）に当てられる。既存の照合の流れに乗り、新しい仕組みを作らない
   - 失うもの: どれも LLM の読みで、取りこぼしが残る
2. **ハンズオンの依頼文だけを絞る**
   - 得るもの: 記事の直しだけで済む
   - 失うもの: 試走では絞っても 10 分を超えた。ほかの題材・ほかの利用者で同じことが起きる
3. **試作の実装役が目安を超えたら止める門（hook か dispatch の判定）を足す**
   - 得るもの: 機械で止まる
   - 失うもの: 止めた後に作り直す時間がかかり、早く示すことに届かない。判定と hook を変える重い直しになる

## Decision
1 を選ぶ。3 は、1 で再発が止まらなかったときに、実測を添えて別の spec にする。

## Consequences
- S の草案は要件が少なめになり、公式のルールの細部は非目標の「足すなら」に並ぶ。人は試作を触ってから足すかを決める
- 照合役の ng が 1 種類増える。main が非目標へ移すか M にする
- S の試作のテストは要件ごとに数件になる。網羅は評価役の要件ごとの確かめが持つ
