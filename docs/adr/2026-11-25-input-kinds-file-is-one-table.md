# ADR: inputs/R<n>.md は表 1 つだけのファイルにし、ほかの行は読めないとする

- 日付: 2026-11-25
- 状態: Accepted
- spec: docs/specs/2026-11-25-input-kinds-table
- 前の ADR: docs/adr/2026-11-25-input-kinds-table.md（表の置き場と止める場所はそのまま。表のファイルの形だけを変える）

## Context
R3 の high が 3 巡続いた。1 巡目は表の後に文を挟んだ fail の行を見落とした。2 巡目は、文の後の行も読むようにしたら、後ろの別の表の行まで読んだ。3 巡目は、別の表で読むのを止めたら、同じ見出しの 2 つ目の表の fail の行を見落とした。どの巡も、表の前後に文や別の表があってよいという前提のまま、どの行が入力の種類の行かを読む側が見分ける規則を 1 つずつ足していた。

## 直し方
- 直し方: 入力の約束を変える
- 退けた: 要らなくする（R1 が `inputs/R<n>.md` の表の行の数・欄・今の結果を見ることを求め、R3 が fail の行を挙げることを求めるので、表を読む処理そのものは無くせない）

## 選択肢
1. **ファイルは、見出しの行・区切りの行・データの行だけの 1 つの表か、`- 入力の種類: なし（<理由>）` の 1 行だけとする。空行はファイルの末尾にだけ許す。ほかの行（文・別の見出し・2 つ目の表・表の途中の空行）が 1 つでもあれば「表が読めない」とし、その行を出す**
   - 得るもの: どの行を読むかを見分ける規則が要らない。表の後に何かを足した事故は、全部「読めない」で止まる（見落とす向きに倒れない）
   - 失うもの: 評価役は補足を表の外に書けない。前の巡の表に行を足すときは、同じ表の中に足す
2. **同じ見出しの表が出たら見出しと区切りを飛ばして読み続ける（今の継ぎ足しを続ける）**
   - 失うもの: 3 巡続いた同じ形の継ぎ足しになる。次の形（見出しの崩れた 2 つ目の表など）でまた見落とす

## Decision
1 を選ぶ。dispatch・handoff・check はどれも同じ読み方（1 つの関数）を使い、ファイルの形が崩れていれば同じ「表が読めない」の誤りを出す。評価役の定義には、ファイルは表 1 つだけで、前の巡の表があれば同じ表に行を足すと書く。

## Consequences
- 表の外の文・2 つ目の表は、dispatch・handoff・check のどこでも「表が読めない」になる
- 評価役が補足を書きたいときは、表の行の欄（期待など）に書く
