# ADR: 入力の表の今の結果を実装役が変えないよう、実装役の定義に規則を足す

- 日付: 2026-11-26
- 状態: Accepted
- spec: docs/specs/2026-11-26-implementer-input-table

## Context
体験会のリハーサルで、実装役が `inputs/R<n>.md` の今の結果を pass に書き換え、handoff が拒んで main が戻す往復が 2 回出た。実装役の定義は入力の表に触れていない。

## 選択肢
1. **実装役の定義に規則を 1 項足す**
   - 得るもの: 実装役が読む唯一の指示に入る。直すのは文だけ
   - 失うもの: 従うかは機械で確かめない
2. **handoff が dispatch の時点の表と比べ、今の結果などの書き換えを拒む**
   - 得るもの: 機械で止まる
   - 失うもの: 表の写しを state に持つ仕組みが要る。今は拒んだ後の往復が 1 回で済むので、まず 1 を入れて次の run で測る
3. **dispatch の出力に規則を足す**
   - 失うもの: dispatch の出力は main だけが読み、実装役には渡らない

## Decision
1 を選ぶ。次の run でも今の結果の書き換えが出たら、2 を足す。

## Consequences
- 実装役の 4 つの定義が同じ文で規則を持つ
