# 2 段の相談の判定に確かめられない件数を添え、読み直しは検証役で代える

- 状態: 採用
- 日付: 2026-11-24

## 背景
#4 で相談を 2 段（fable-advisor の推奨 → advice-checker の反証）にした。独立レビューで、全部が「確かめられない」でも `反証なし` になる、main が引いた行を読み直すかが 2 通りに読める、呼べない環境と opus-advisor を名指ししたときの扱いが無い、朝の報告に 2 段目の判定が残らない、などが出て、Issue #5 に残した。

## 決定
- 判定の値は `反証あり` / `反証なし` の 2 つのまま、判定の行に `（確かめられない <n> / <主張の数>）` を添える。反証なしでも主張ごとの結果を書く
- 相談役が引いた決定の読み直しは、advice-checker が `引いた決定:` の主張を `成り立つ` としたときは、その検証で代える。反証ありで直させた推奨（検証し直さない）と、主張が `確かめられない` だったときは、main が引いた行を読み直してから使う。読み直しは引いた行が書かれたとおりかを確かめるだけで、推奨への反証を探すことではない
- 人が opus-advisor を名指ししたときは、opus-advisor を 1 段目にして、2 段目の advice-checker は同じく回す
- 呼べない段は `<agent>: unavailable（理由）` と書いて進む

## 退けた案
- 判定に 3 つ目の値（`確かめられない`）を足す: 判定を読む側（10 回の読み取り、朝の報告）の分け方が増える。件数を添えれば、全部が確かめられない回も見分けられる
- 名指しの opus-advisor では 2 段目を回さない: 2 段目を外す理由は、名指しのモデルが Opus に変わることには無い
- main に毎回読み直させたまま残す: 「main は反証しない」と 2 通りに読める形が残り、検証役と同じ読みを重ねる
- 読み直しをすべて検証役で代える: 直した推奨と確かめられない主張は、誰も読まずに届く

## 結果
- 判定の行の形が変わる。判定の値だけを読む側は変わらない
- 名指しの opus-advisor でも advice-checker の時間と費用がかかる
