# ADR: 夜通しの NOTE は、見込みの長さが 60 分を超える run にだけ出す

- 日付: 2026-11-26
- 状態: Accepted
- spec: docs/specs/2026-11-26-night-notes-short-run

## Context
preflight の check は、keep-awake・バッテリー・macOS の自動更新・見回り役の NOTE を、run の長さによらず lint と承認のたびに出す。体験会のリハーサル 3 回（予算 30 分の昼の run）でも毎回出て、agent が出力から grep -v で隠すか、「影響しない」と説明していた。初めての人には関係の無い警告で、読む量を増やす。

## 選択肢
1. **見込みの長さ（予算＋マージ後の予算＋前に並ぶ分）が 60 分を超えるときだけ出す**
   - 得るもの: SSO の検査が使う見込みの夜の終わりと同じ材料で決まる。S の既定（30 分・マージ後なし＝60 分）で消え、M の既定（90 分）以上では今のまま出る
   - 失うもの: 60 分以下の run を夜に回すと、眠り・再起動の警告が出ない（短い run は寝る前に終わる見込みなので害は小さい）
2. **範囲が「PR まで」のときだけ出さない**
   - 失うもの: 「PR まで」でも長い夜の run はありうる。範囲は長さを表さない
3. **lint では出さず、approve でだけ出す**
   - 失うもの: 承認の前に人に示す材料から消える。体験会では approve の出力にも出るので目的に届かない

## Decision
1 を選ぶ。閾値は 60 分の定数にし、設定は足さない（YAGNI）。予算が読めない spec は長さが分からないので、止める側（出す側）に倒す。

## Consequences
- 体験会の S の run では、lint と承認の出力から夜の 4 つの NOTE が消える
- SSO と GDD の検査は長さによらず今のまま
- 目的の spec の承認（approve --goal）は、子の spec を夜通し回す前に人が見る唯一の承認なので、予算によらず夜の NOTE を出す（評価の 2 巡目で、main から入った --goal の経路で消えると分かった）
