# ADR: 夜の間の承認し直しを、相談役 2 本の起動の記録で通す

- 日付: 2026-11-26
- 状態: Accepted
- spec: docs/specs/2026-11-26-advisor-reapproval

## Context
`autopilot.py approve` は人の発言を transcript の origin で確かめるので、夜の間に承認し直しが要ると、その spec と依る spec が朝まで止まる。全 repo の block 4 件は全部この理由だった。人は、途中の承認は相談役の Fable でよく、ただし Fable の直しは裏取りで誤りが複数見つかったので、裏取りはしてほしいと決めた。

## 選択肢
1. **approve に `--by-advisor` を足し、spec の変更より後にこのセッションで起動した fable-advisor と advice-checker の記録（meta.json と transcript）に、`承認: 可` と `判定: 反証なし（確かめられない 0 / <n>）` があるときだけ通す**
   - 得るもの: main の自己申告では通らない（handoff が実装役の起動を確かめるのと同じ記録を読む）。裏取りの 2 段が外れない。人の発言の門はそのまま残る
   - 失うもの: host の記録の形に頼る。相談役が否と言うか反証が出たら、朝まで止まる
2. **main が相談役の返答を `--by` に写して approve する（記録を読まない）**
   - 失うもの: 相談役を回さずに承認し直す事故を止められない。人の発言の門を入れた理由（agent が事故で自分を承認し直すのを止める）が崩れる
3. **承認し直しが要る spec を block せず、変えた要件だけを park に積んで進める**
   - 失うもの: 承認の後に要件を変えると check が止まる仕組み（spec のハッシュ）を緩めることになる。人の決定（Fable に承認させる）に合わない

## Decision
1 を選ぶ。判定の形は 1 つ（`承認: 可` と `反証なし（確かめられない 0）`）に決め、ほかは全部止める。初回の承認と、自走の範囲を変える承認し直しには使わない。

## Consequences
- 夜の間に止まるのは、相談役が否と言ったか、検証で反証・確かめられない主張が出た承認し直しだけになる
- 朝の報告に、相談役で承認した巡が出るので、人が読み直す
- host が subagent の記録の形を変えると、`--by-advisor` は通らなくなる（止まる向きに倒れる）
