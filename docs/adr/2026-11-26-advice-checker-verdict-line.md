# ADR: advice-checker の判定の行の形は、定義の出力の節の 1 か所だけで決める

## 状況
PR 39 で、夜の承認し直しの門（advisor_approval.py）は advice-checker の返答の `判定: 反証なし（確かめられない 0 / <n>）` の形だけを通すことにした。手元の返答 66 本のうち 8 本が括弧を欠いていた。括弧を足した定義の変更（commit 012c423）の後の起動では括弧の欠けは出ていないが、定義の守ることの節（28 行目）には括弧の無い `判定: 反証なし` が残り、出力の節（34 行目）と形が食い違う。28 行目は反証が見つからないとき、つまり門が通す唯一の場合に読まれる行である。

## 決定
28 行目から判定の行の literal を外し、出力の節の形で判定を書くよう指す文にする。形の正本は出力の節の 1 か所にする。定義の判定の行の例が門の通す形と合うことを、テストで突き合わせる。

## 退けた案
- 直さない（012c423 の後は括弧の欠けが 0 本なので、件は閉じたと扱う）: 食い違いが定義に残り、定義の改稿や model の変更で 28 行目が勝つ余地が残る。人は直すよう頼んだ
- 28 行目にも括弧つきの形を写す: 形の写しが 2 か所に残り、片方だけ直す食い違いがまた起きうる
- 門で括弧の無い `判定: 反証なし` も通す: 確かめられない主張が何件あっても通ることになり、commands/autopilot.md の夜の承認し直しの条件（確かめられない 0 のときだけ通る）を緩める
