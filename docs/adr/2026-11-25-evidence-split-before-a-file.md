# ADR: qa.md の証拠は、区切りの後ろが続き（`::`）か repo にあるファイルのときだけ区切る

## 状況
`autopilot.py check` は、qa.md の pass の証拠に並べたテストを `・`・`、`・`,` で区切って探す。区切りかどうかは、記号の直後に「空白・区切り・`:`・括弧・バッククォートを含まない語」と `::` が続くか（`EVIDENCE_SEP` の先読み）だけで決めている。jest の `describe` の名前のように、`::` の前の名前の中に `・`・`、` があると、名前の後半を path と読む。`core.test.js::得点・レベル::1 行消すと、100 点` は `core.test.js::得点` と `レベル::1 行消すと、100 点` に分かれ、`check` は「レベル が無い」で落ちる（2026-11-24 の試走で、テスト名を直すタスクが 1 往復増えた）。

## 決定
先読みで区切りの候補を見つけた後、候補の後ろの path の部分が空（`::<名前>` の続き）か、repo の root から見てファイルであるときだけ区切る。どちらでもなければ、記号ごと前のテストの名前に戻す。区切りの記号と `::` の続きの書き方は今のまま受ける。

## 退けた案
- path の形（`/` を含む、`.<拡張子>` で終わる）で区切る: ファイルを読まずに決まるが、`v1.2` のような名前の一部を path と読み、書き間違えた path と名前の一部を同じ形で見分けられない
- 評価役に、名前に区切りの記号を含むテストはバッククォートで 1 つずつ囲ませる: 評価役の 3 つの定義と qa.md の雛形の文を変える必要があり、書き忘れると今と同じに落ちる
- 区切りの記号を `・` だけにする: `、`・`,` で並べた既存の証拠が読めなくなる

## 結果
- 区切りの後ろに、repo に無いファイルの path を書いた証拠は、前のテストの名前の一部と読まれ、「<前の path> に「<名前>・<書いた path>…」が無い」で落ちる（今の「<書いた path> が無い」より読みにくいが、落ちることは変わらない）
- 区切りの候補ごとに 1 回、ファイルがあるかを見る（証拠の欄の数だけで、走査の上限は今のまま）
