# ADR: 外部サービスの最新の情報は、playbook で調べさせ、出典を spec の前提に残させる

## 状況
人は、AWS などの動きが速いサービスを使う作業で、古い情報のまま作業することがあると言った。playbook の external-service は、本物で確かめる手順と、エラーコードの区別を求めるが、使う機能の今の仕様と変更の履歴を調べることは求めていない。iac は道具の版を repo の固定に合わせると書くが、使う引数がその provider の版にあるかの突き合わせは求めていない。spec の前提の節には URL の行がある（後ろに文字を書けない）。

## 決定
1. external-service の「spec を書くとき」に、使う機能ごとに、今の公式の文書・変更の履歴（What's New・リリースノート・API の changelog）・事例を調べてから要件と前提を書き、`- 前提: <確かめた振る舞い>（確認日 YYYY-MM-DD）` と `  - URL: <出典>` で残すよう足す。事例は `- 普通のやり方:` の出典に書く
2. iac の「spec を書くとき」に、使う資源・引数が入った provider の版を CHANGELOG で調べ、repo が固定する版と比べた結果を、同じ形で前提に残すよう足す
3. 利用者の手元に最新を調べる skill があれば、それに従ってよいと書く。特定の skill の名前は書かない（公開の plugin で、利用者の手元に無いため）

## 退けた案
- lint で確認日の行を求める: 外部サービスを使う spec かを lint は見分けられず、使わない spec を止める。まずは playbook の指示で回し、守られないことを観測してから機械にする
- spec の雛形（templates/spec.md）の前提の注記にも足す: 外部サービスを使わない spec にも読ませる文になる。playbook は選んだ spec だけが読む
