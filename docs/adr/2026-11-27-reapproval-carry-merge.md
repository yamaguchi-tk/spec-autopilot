# ADR: 承認し直しで、コードが同じときだけマージとデプロイの記録を持ち越す

- 日付: 2026-11-27
- 状態: Accepted
- spec: docs/specs/2026-11-27-reapproval-carry-merge

## Context
承認し直し（lineup.begin）は前の巡の記録を全部 history に移し、awaits は approved_at より後だけを読む。要件の文だけを直した spec でも、マージとデプロイをやり直さないと done に届かず、別の repo の spec がこれで block した。check は今の HEAD が最後のマージの head に含まれることを求めるので、spec.md を直した commit だけで「含むマージ」が無くなる。

## 選択肢
1. **案 A: 最後のマージの head と今の HEAD で、docs/specs と docs/adr の外の差分が無いときだけ、merges と待ちの記録を持ち越す。レビューと QA は数え直す**
   - 得るもの: 本番に出たものが変わっていない事実を git で決められる。コードが変われば今までどおり新しいマージが要る
   - 失うもの: 持ち越した spec では、spec の置き場の直しがマージの PR に入らない（マージの後の qa.md・state.json と同じく作業ブランチに残る）。check の「含むマージ」の判定に分岐が 1 つ増える
2. **案 B: 文が変わった要件の記録だけを数え直し、変わらない要件の pass とレビューも持ち越す**
   - 失うもの: 要件ごとの持ち越しの判定が check の全体に広がる。レビューが差分の全体を見た事実を要件ごとに分けられない
3. **持ち越さず、spec の置き場だけの PR を作ってマージし直す**
   - 失うもの: マージで自動に動くデプロイがまた走り、その成功を待つ。観測した block と同じ手間が残る

## Decision
1 を選ぶ。持ち越すかの判定は git の pathspec に任せ、決められないときは持ち越さない（止める側に倒す）。done の後の直しと、着手の block の後は対象にしない。

## Consequences
- 要件の文だけの承認し直しで、マージとデプロイをやり直さずに done に届く
- 持ち越したかは approve の出力に出るので、朝の報告で人が読める
- test_overnight.py の「承認し直しは新しい巡を数え直す」テストは、コードを変えた形と持ち越す形の 2 本に分ける
