# ADR: 評価役の起動を hook が記録し、記録の無いままの直しを止め、梯子の巡は累計で数える

- 日付: 2026-11-27
- 状態: Accepted
- spec: docs/specs/2026-11-27-ladder-counted-by-script

## Context
人が「3巡も指摘されたら設計に戻って欲しいというフローがあると思うが　なんで5回も回っている？」「GDDでの反省や過去のセッションでの反省点がまったくいかされていない　どうするのが最善？　どうしたら守れる？」と問うた。

docs/specs/2026-11-27-consent-adr-fix-ladder では、評価役が 4 巡とも high を出したのに、梯子（同じ要件で 2 巡続いたら原因を調べ、3 巡続いたら作り方を変える）は一度も上がらなかった。state.json の reviews は [R1,R8]・[]・[R1]・[]・[] で、R1 の fails は 2 件、streak は全要件 0 である。原因は 2 つある。

1. 巡の記録（`autopilot.py review`）を打つのは main だけで、打たずに次の直しへ進める。評価役の high を記録しないまま直した巡と、記録が断られて飛ばした巡があった。
2. high も失敗も無い巡で数えが 0 に戻る（autopilot.py の cmd_review）。main が検査を回し直した「再実行」の high none でも戻る。

GDD からの移行の ADR（docs/adr/2026-11-15-switch-harness-to-spec-autopilot.md）は「文の指示でなく機械の検査で固める」と決めたが、梯子が数える材料は main の申告のままだった。docs/adr/2026-11-25-input-kinds-table.md も、同じ要件で high が 4 巡続いた事例を記録している。

## 選択肢
1. 要らなくする: 今の手順（commands/autopilot.md の C の 4 の「結果を CLI review で記録する」）に任せ、何も足さない
   - 得るもの: 変更が無い
   - 失うもの: 今回、手順があっても記録を 2 巡飛ばした。数える役と破る役が同じ main のまま
2. 入力の約束を変える: 評価役が自分で `autopilot.py review` を打つ
   - 得るもの: main を記録の道から外せる
   - 失うもの: 評価役の指摘は main が回し直して再現したものだけを採る（commands/autopilot.md の C の 4）ので、評価役は採る high を決められない。main が評価役を起動せずに直しへ進む抜けも残る
3. 設計を変える: 評価役の起動を agent_gate（評価役と実装役の起動が必ず通る PreToolUse hook）が state.json に記録し、最後の評価役の起動より後に review の記録が無ければ実装役の起動を拒む。梯子の巡は、要件ごとに high か失敗のあった巡の累計にし、rework でだけ 0 に戻す
   - 得るもの: 記録の抜けが次の直しの前で機械的に止まる。再実行の high none で数えが戻らない。3 巡目で必ず作り直しに入る
   - 失うもの: 関係の薄い high が 3 回重なっても作り直しに入る。hook が state.json に書く道が 1 本増える
4. 局所の継ぎ足し: 再実行の道の `review` に印を付け、印のある high none だけは数えを戻さない
   - 得るもの: 変更が最小
   - 失うもの: 記録を飛ばす抜けは残る

## Decision
3 を選ぶ。spec の目的（梯子の判定を main の申告に頼らず、3 巡で必ず設計に戻す）に届くのは 3 だけである。数える単位は要件ごとのままにし（作り直しの入口の `autopilot.py rework` が要件ごと）、spec 全体の累計にはしない。

- 直し方: 設計を変える
- 退けた: 要らなくする（今の手順のままでも、main が評価役の結果を記録せずに直しへ進んだ巡が 2 巡あり、梯子が上がらなかったので目的に届かない）
- 退けた: 入力の約束を変える（評価役は採る high を決められず、main が評価役を起動しない抜けも残るので、判定を main の申告から外すという目的に届かない）

## Consequences
- docs/adr/2026-11-15-switch-harness-to-spec-autopilot.md の「失敗も high も無い巡で 0 に戻す」を、この ADR で置き換える。references/dead-end.md と commands/autopilot.md の数え方の文も同じ変更で直す
- 評価役の結果を記録し忘れると、次の実装役の起動が hook で止まる
- 予算の 2 倍で放す時間の引き金は変えない。予算を超えた spec がその後に何巡使ったかを、この変更の後の state.json で数えてから決める
