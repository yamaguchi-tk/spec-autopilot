# ADR: テストの時間は、CI の並列と、遅い照合の 1 か所の直しで減らす

## 状況
今夜の 2 本の spec（advisor-reapproval・goal-split）で、テスト全体を実装役・評価役・CI の 3 か所で回していた。過去の spec 12 本のうち、`- 回帰テスト:` にテスト全体を書いたのはこの 2 本だけで、残りの 10 本は関係するテストのファイルを並べていた。評価役の定義は `- 回帰テスト:` があればそれを回すので、重複の原因は定義ではなく spec の書き方だった。CI は並列にせず 1 本で回し、PR 48 で 7 分 44 秒かかった。手元の `-n auto` は 3 分 5 秒（負荷の高い機械で）。check の時間を測るテストが負荷で 1 回落ちた。tasks.md の `[` が続く行で、`TASK` の正規表現が行の長さの 2 乗の時間を使い、49 行で CPU 3.3 秒かかる（上限 5 秒のテストが負荷で落ちる）。

## 決定
1. CI に pytest-xdist を版を固定して入れ、`-n auto` で回す
2. `TASK` の照合を、今と同じ結果のまま、行の長さに比例する時間にする
3. repo の CLAUDE.md に、spec の `- 回帰テスト:` には変えるスクリプトを読むテストのファイルを並べ、全体は CI に任せると書く。テストを回すコマンドも `-n auto` にする

評価役の定義（agents/autopilot-reviewer*.md）は変えない。

## 退けた案
- 評価役の定義を変え、`- 回帰テスト:` があってもテスト全体を回さないようにする: 定義はもともと全体を求めていない。直すのは spec の書き方で、定義を変えても書き方は直らない
- テストの CLI を subprocess でなく同じプロセスで呼ぶ: 1 回の起動は約 0.1 秒で、10077 回の起動の多くは入口を通すためのもの。入口を通さないテストに変えると、hook と CLI の入口の確かめが抜ける
- 時間を測るテストを、壁時計でなく子プロセスの CPU 時間で測る: 揺れは消えるが、照合が 2 乗の時間を使うこと自体は残る。照合を直せば、今の 5 秒の上限に十分な余裕ができる
