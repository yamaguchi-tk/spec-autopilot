# ADR: 新しく作る repo の M でも、承認の前に試作を作る

- 日付: 2026-11-27
- 状態: Accepted
- spec: docs/specs/2026-11-27-new-repo-m-prototype

## Context
PR 86 の試走（2026-11-27、Sonnet 5.5、新しい repo、ブラウザのテトリス）で、最初に触れたのは送信から 8:49 だった。照合役が最初に S と見積もり、承認の前の試作を作ったからで、試作は 278 行になり草案は M に変わった。今の門は承認の前の試作を大きさ S だけに許すので、最初から M と見積もられた回では、触れるのは人の OK と実装の後の約 12〜13 分になる。人は「R2 は fail として記録し、承認の前の M の試作を次の spec にする」と決めた。docs/adr/2026-11-27-new-repo-m-one-implementer.md の選択肢 3 がこれに当たる。

## 選択肢
1. **新しく作る repo で、依る spec の無い M に限って、承認の前の試作を許す**
   - 得るもの: 最初から M と見積もられても、草案と一緒に触れるものが出る。新しく作る repo では、試作は空の repo に書くだけで、既存のコードを壊さない
   - 失うもの: 「承認の前にコードを書かない」の例外が広がる。M の試作は S より大きく、草案の提示が少し遅れうる（R2 で測る）
2. **すべての M で試作を許す**
   - 失うもの: 既存の repo では、承認の前に既存のコードを書き換えることになる。大きさを数える起点（init の時点）との差分が承認の前に育ち、影響範囲の照合と混ざる
3. **大きさの見積もりを試作の後に回し、まず S で試作を作ってから決める**
   - 失うもの: 大きさの行を偽って書くことになり、lint と承認の判定（S は試作の差分で確かめる）と食い違う
4. **何もしない（S の試作だけ）**
   - 失うもの: 最初から M の回で 10 分に届かない

## Decision
1 を選ぶ。依る spec のある M は、前の spec の変更がまだ載っていない木に試作を書くことになるので外す（S と同じ扱い）。

## Consequences
- 新しく作る repo の M の試作は、S と同じく承認の後の handoff で閉じ、試作で済んだタスクを `[x]` にして残りを実装する
- 既存の repo の M と L は、承認の前にコードを書かない
- R2 の実測が 10 分を超えたら、照合役と試作の並行などを人と決める
