# /spec

依頼: $ARGUMENTS

この本文の `CLI <sub> ...` は、`python3 "${CLAUDE_PLUGIN_ROOT}/scripts/autopilot.py" <sub> ...` をそのまま実行することを指す（シェル変数に入れない）。`/autopilot` の A（壁打ち）の、依頼に要件と完了条件が明示されていないときの手順を、ここに 1 か所で書く。承認のあと（自走）は `commands/autopilot.md` の C に従う。

## 0. 最初の返事の前に判断する

依頼に、**要件**（何を作る・変えるか）と**完了条件**（何が見えたら満たしたと言えるか。Issue の受入条件を指すのでもよい）の両方が明示されているかを判断する。迷ったら明示されていないとして扱う。

- 両方明示されている: 壁打ちに入らず、まず `commands/autopilot.md` の「## 0. 準備」（worktree で始める・既存の repo の下調べ・GDD の確かめ・verify skill）を済ませ、A の 0 から B の手順（最初の返事から lint を通した草案を示す）で進める。
- どちらかが無い: 下の壁打ちに入る。`commands/autopilot.md` の「## 0. 準備」は、壁打ちの間は Read・Grep・Glob で読むだけにし、worktree と verify skill は「固めて」の前に用意する（5 の 1）。

## 1. 壁打ちの間は速く返す

- 「固めて」の前の返事は、それぞれ 60 秒以内に返す。Agent（subagent・相談役・照合役・検証役）も `CLI` も呼ばない。コードを読むなら Read・Grep・Glob で、依頼に関わる数か所だけにする（全文を読み込まない）。
- 1 回の返事に、問いは 1 つだけ入れる。長い説明・案の比較・lint の話は書かない。一発で正解を出さず、人の返事で直しながら熟成させる。
- 人が「任せる」と言ったら、推奨で決めて次に進む。

## 2. 最初の返事の型

次の 2 つだけを返す。

1. 4 項目のたたき台（推測で埋め、足りない所は「仮」と書く）: **要件**・**完了条件**・**制約**（予算・範囲・守るもの）・**実装方法**（一言）
2. 問い 1 つ。答えで 4 項目のどれかが最も変わる問いを選ぶ。

## 3. 具体例で完了条件にする

依頼か人の返事に、何が見えたら満たしたかを言えない語（例:「賢くなる」「使いやすい」「速くなる」）が要件か完了条件として出たら、次の返事で「何が見えたら完了か」の具体例を 2〜3 個、番号つきで出して選ばせる（これがその返事の問い 1 つになる）。人が選んだ例（番号の返事、または直した例）を、`〜とき、〜になる` の形の完了条件としてたたき台に入れ、その語はたたき台から外す。選ばれなかった例は完了条件に入れない。

## 4. 往復

返事のたびに、たたき台の 4 項目を直して短く示し、問いを 1 つ返す。完了条件が全部 `〜とき、〜になる` の形になり、目的そのものを確かめる要件が 1 つ決まったら、「固めてと言ってくれれば spec にします」と添える。人が「固めて」と言うまで、spec・ADR・lint・照合役には進まない。

## 5. 「固めて」と言われたら

人が「固めて」と言ったら、次を順に 1 回ずつ行う。

1. `commands/autopilot.md` の「## 0. 準備」を済ませる（worktree で始める・既存の repo の下調べ・GDD の確かめ・verify skill の用意。済んでいる分は繰り返さない）。そのあと `CLI init <slug>` を実行する（この会話で init していなければ。init 済みならそのまま使う）
2. playbook を選んで読み（`commands/autopilot.md` の A の 0）、spec.md と ADR を書く（`commands/autopilot.md` の B の 1・2）。たたき台の完了条件を要件の `〜とき、〜になる` にし、QA の方向性に `- 目的の確かめ: R<n>`（目的に届いたかをその要件の QA で確かめる）か `- 目的の確かめ: マージ後（<確かめ方>）` の行を 1 本書く
3. `CLI lint <dir>` を通す。ERROR は直す
4. `autopilot-spec-checker` agent を前景で 1 回起動する（`commands/autopilot.md` の B の 3 と同じ。渡すのは spec のディレクトリだけ）。`ng` は直し、直したら `CLI lint <dir>` だけを通し直す（照合役は回し直さない）
5. S と、新しく作る repo の M（`- 依る spec:` の行が無いもの）では、`references/small-prototype.md` に従って試作を作る（壁打ちの道では、ここで初めて作る）
6. spec を示して OK を求める（示す中身は `commands/autopilot.md` の B の 4）。この turn では approve を打たない

人の OK の返事を受けたら、`commands/autopilot.md` の B の 5（approve）に進み、承認のあとは C で自走する。OK でなく直しの返事なら、spec を直して `CLI lint <dir>` を通してから示し直す（照合役は回し直さない）。
