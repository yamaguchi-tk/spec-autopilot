# 既存の repo（docs/specs・docs/adr の外に git が追っているファイルがある repo）

既存の repo の spec では、playbook の選びによらずこのファイルに従う（`commands/autopilot.md` の A の 0・3 と B の 1 から読む。新しく作る repo では読まない）。

## 影響範囲と変えない挙動（B の 1）

- 「## 影響範囲」と「## 変えない挙動」を埋める（`CLI lint` が求め、形の合わない行・init の時点の commit と合わないパスと名前は ERROR にする）
- 影響範囲は 1 行に 1 つ、役ごとに次の形で書く。パスと名前はバッククォートで囲んでもよく、`<行>` は `<行>-<行>`・`<行>〜<行>` の範囲でもよい。補足は次の行に `  - メモ: <内容>`
  - `- 変える: <path>:<行>（<名前>、<名前>）`（ファイル全体なら `（全体）`）・`- 新規: <path>`
  - `- 呼び出し元: <path>:<行>`（無ければ `なし`。必須）・`- 別の実装: <path>:<行>`・`- 手本: <自由>`
  - `- 同じ入力: <名前>、<名前>`（変えるコードが読む設定キー・環境変数・テーブル名など。無ければ `なし`。必須）。lint がこの名前で grep して別の実装を数えるので、`id` のようなよくある語ではなく、その入力だけを指す名前を書く
- `- 回帰テスト: <コマンド>` に、変えるモジュールを参照する既存のテストだけを回すコマンドを書く（全量は CI に任せる）
- 変えない挙動には、spec の外で今のまま残す挙動を、それを確かめる既存のテストと一緒に書く（既存の事実と違う前提と、呼び出し元・別の実装の直し漏れが、手戻りの主な原因だった）

## 大きさの数え方（A の 3）

- 大きさは `CLI lint` が数えて決める（要件の数だけでは決めない）。数えるのは次の 3 つ（どれもテストと `docs/` の下を除く。`docs/` の外の `.md` は数える）
  - 変えたファイル: `- 変える:`・`- 新規:` のパスと、init の時点の commit から今の作業ツリーまでの差分（未追跡のファイルを含む。統合先〔`origin/HEAD`〕を取り込んだだけのファイルは数えない。`origin/HEAD` が引けなければ `git remote set-head origin --auto` で直してから lint し直す）
  - 呼び出し元: `- 変える:` の名前を含むほかのファイルと、`- 呼び出し元:` のパス（`（全体）` で変えるファイルの呼び出し元は、書いた分だけになるので書き漏らさない）
  - 別の実装: `- 同じ入力:` の名前を含むほかのファイルと、`- 別の実装:` のパス
- 変えたファイルが 1 つで、呼び出し元と別の実装が合わせて 2 つまでなら S、6 つ以上なら L、ほかは M
- `- 大きさ:` が数えた大きさより小さいと lint が ERROR にするので、数えた大きさに上げる。人の発言で小さくする道は無い
- 初回の合意で数えた大きさが L なら、上げずに `commands/autopilot.md` の A の 3 の L の項のとおり spec を分ける
- block・done の後の合意し直しでは、lint は L を理由には止めない（実装はもう同じブランチにあるので、`commands/autopilot.md` の C の 5 で PR を分ける）
