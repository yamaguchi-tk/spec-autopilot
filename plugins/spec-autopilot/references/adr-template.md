# ADR の雛形

書くのは次の 2 つのときだけ。

- 合意のとき: 作り方の選択（選んだ案と退けた案）
- 自走のとき: 設計を変える決定（行き詰まりの作り直しを含む）。名前・置き場所などの小さい決定は ADR にせず、tasks.md の該当タスクの下に `  - メモ: ...` の行で残す

置き場所は `docs/adr/YYYY-MM-DD-<slug>.md`。repo に ADR の規約（連番など）があればそれに従う。

```markdown
# ADR: <決めたことを 1 文で>

- 日付: YYYY-MM-DD
- 状態: Accepted | Superseded by <ADR>
- spec: docs/specs/<spec>

## Context
<何が問題だったか。行き詰まりなら、失敗の証拠（コマンドの出力・テストの結果）>

## 選択肢
1. <案>: <得るもの・失うもの>
2. <案>: ...

## Decision
<選んだ案と理由。spec のどの要件・制約を根拠にしたか>

## Consequences
<この決定で変わること、残る不利益>
```
